# Flowza — тестовый Telegram-бот клиента

Python-бот по ТЗ версии 1.1: **Қазақша / Русский**, вопросы по очереди, проверка данных, исправление анкеты и отправка заявки в Flowza CRM. Работает с одним настроенным мастером. Клиент пишет в личный чат, мастер получает заказ `NEW` с источником `BOT` и уведомление в CRM. Стоимость и время окончательно подтверждает мастер.

ИИ и платный конструктор не требуются. Локально бот работает, пока включён компьютер и запущены CRM и бот. Для круглосуточной работы понадобится постоянно работающий компьютер или сервер.

## 1. Подготовить CRM — обязательно один раз

В актуальной версии [Flowza CRM](https://github.com/KuatBakyt/flowza-crm) уже есть
атомарный `/api/v1/bot/orders/`. Обновите CRM и выполните её миграции по README.
Копировать папки или менять settings/urls больше не нужно. Бот остаётся в этом
отдельном репозитории и подключается к CRM через API.

В CRM должен быть активный пользователь **MASTER** с профилем, включённой доступностью и хотя бы одной активной специализацией. Для теста используйте отдельного тестового мастера. UUID мастера и услуг бот получит через API — копировать их не нужно.

## 2. Создать бота в Telegram

Откройте официальный [@BotFather](https://t.me/BotFather), выполните `/newbot`, задайте название и уникальный username. Полученный токен сохраните только в `.env` на своём компьютере. Не публикуйте токен в GitHub и не отправляйте его клиентам.

## 3. Запуск на Windows

Установите Python 3.12 или новее. Откройте PowerShell:

```powershell
git clone https://github.com/KuatBakyt/testbot_client_flowza.git
cd testbot_client_flowza
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

Заполните:

```dotenv
TELEGRAM_BOT_TOKEN=токен_из_BotFather
CRM_API_URL=http://localhost:8000/api/v1/
CRM_PHONE=номер_тестового_мастера
CRM_PASSWORD=пароль_тестового_мастера
BOT_TIMEZONE=Asia/Almaty
BOT_STATE_PATH=data/bot.sqlite3
BOT_BUSINESS_NAME=Flowza
```

`localhost` подходит, если бот и CRM запущены на одном компьютере. Для удалённой CRM укажите её HTTPS-адрес с `/api/v1/`. Виртуальное окружение активировать не обязательно — команды ниже вызывают его Python напрямую.

Проверка соединения без сообщений клиентам:

```powershell
.\.venv\Scripts\python.exe -m flowza_bot --check
```

После успешной проверки:

```powershell
.\.venv\Scripts\python.exe -m flowza_bot
```

Откройте своего бота в Telegram и отправьте `/start`. Остановка: **Ctrl+C**. Для другого файла настроек используйте `--env путь\к\.env`.

На Linux/macOS: `python3 -m venv .venv`, `.venv/bin/python -m pip install -r requirements.txt`, `cp .env.example .env`, `.venv/bin/python -m flowza_bot`.

Если у бота уже включён webhook, запуск останавливается. Для осознанного перехода на polling: `python -m flowza_bot --reset-webhook`. Накопленные обновления не удаляются. Не запускайте одновременно другой процесс с тем же Telegram-токеном.

## Диалог и команды

Выбор языка → согласие → имя → телефон → услуга → описание → адрес → район → желаемое время → 1/2/3 часа → сводка → отправка.

- `/start` — начать или продолжить незавершённую анкету.
- `/new` — новая анкета; после успеха кнопка «Новая заявка» делает то же самое.
- `/language` — смена языка с сохранением ответов и текущего шага.
- `/back` — предыдущий вопрос.
- `/cancel` — отмена до отправки.
- «Изменить» в сводке — выбрать поле и вернуться к сводке после правки.

Дата вводится как `05.10.2026 10:00` в `BOT_TIMEZONE`, в CRM отправляется UTC. Дата должна быть в будущем в пределах 365 дней. Например, 10:00 Алматы соответствует 05:00 UTC. Бот не резервирует время: мастер подтверждает заказ в CRM.

Телефон принимается текстом или собственным контактом Telegram. Имя, описание и адрес сохраняются на исходном языке. Специализации и районы берутся из CRM. Для перевода названий скопируйте `catalog_labels.example.json` в `catalog_labels.json`, заполните `specializations` по UUID услуг и добавьте в `.env`:

```dotenv
BOT_LABELS_PATH=catalog_labels.json
```

Структура названий: `"specializations": {"uuid-услуги": {"kk": "Сантехникалық жұмыстар", "ru": "Сантехника"}}`. Районы индексируются исходным названием CRM. При отсутствии перевода используется название CRM. Тексты интерфейса находятся в `flowza_bot/locales/ru.json` и `kk.json`; перед публикацией казахскую редактуру следует проверить с носителем языка.

## Что происходит при сбое

SQLite сохраняет язык, шаг, черновик и точный запрос перед отправкой. При таймауте бот не показывает успех, сохраняет запрос и предлагает «Повторить отправку». Повтор идёт с тем же `request_id`; API возвращает тот же заказ. Пока результат неизвестен, нельзя отменять или менять заявку — это защищает от второго заказа. Язык сменить можно.

После подтверждённого отказа валидации можно исправить данные; после занятого времени бот возвращается к выбору даты. Исправленная отправка получает новый ключ. После успеха личные поля анкеты удаляются из локальной сессии, сохраняются язык и номер заказа.

Путь `BOT_STATE_PATH` должен быть постоянным. Не удаляйте базу после таймаута и не меняйте её на новую ради повтора. Файл базы содержит черновики с личными данными: храните его на своём компьютере и не добавляйте в Git. Смена бота или мастера требует отдельной базы, чтобы старые заявки не ушли другому мастеру.

Очередь исходящих сообщений также сохраняется. При редком сбое после отправки Telegram может повторно показать сообщение; заказ в CRM при этом остаётся один. Одновременный запуск двух процессов с одной базой блокируется.

## Проверки

Без Telegram-токена и без Django:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -v
```

Для реального HTTP-теста с копией исходного Flowza CRM:

```powershell
.\.venv\Scripts\python.exe -m pip install -r ..\flowza-crm\requirements.txt
$env:FLOWZA_CRM_PATH = (Resolve-Path ..\flowza-crm).Path
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -v
```

Интеграционный тест поднимает временную базу SQLite и локальный HTTP-сервер. Рабочая база CRM и её `.env` не используются. Проверяются настоящий JWT, каталог, полный диалог, клиент, заказ, уведомление, отклонение чужого мастера, повтор, конфликт ключа и откат ошибочной заявки. В GitHub Actions эти проверки выполняются автоматически.

Сквозной ручной тест Telegram: пройти анкету на каждом языке, увидеть номер, открыть CRM мастера и проверить клиента, услугу, адрес, местное время, `NEW` и `BOT`. Живой Telegram требует собственного токена; автоматические тесты используют подмену Telegram HTTP.

## Типичные проблемы

- **404 при --check**: модуль CRM не установлен, маршрут не добавлен либо API указывает не на обновлённую CRM.
- **401/403**: проверьте номер, пароль и роль MASTER; аккаунт и профиль должны быть активны.
- **Мастер недоступен / нет услуг**: включите доступность и активную специализацию в CRM.
- **409 Telegram**: уже запущен другой бот с тем же токеном или включён webhook.
- **Connection failed**: запустите CRM и проверьте адрес; токен или пароль нигде не печатаются.

Документация протокола: [Telegram Bot API](https://core.telegram.org/bots/api). Исходное ТЗ — версия 1.1 с русским и казахским языками.

## Уведомления мастеру в Telegram

Мастер должен написать **этому же боту** `/start`, затем `/myid`.
Бот покажет личный Chat ID; команда не изменяет анкету. В существующем `.env` добавьте:

```dotenv
MASTER_TELEGRAM_CHAT_ID=123456789
CRM_WEB_URL=https://your-crm.example
```

Подставьте ID мастера и адрес **интерфейса** CRM, не `/api/v1/`.
`localhost:8080` годится только для проверки на том же компьютере; чтобы мастер
открывал CRM с телефона, нужен доступный ему адрес. Запустите `--check`, затем бота.
Проверка выполняет getChat, не отправляя тестовых сообщений мастеру.
Оба параметра можно оставить пустыми — клиентский бот продолжит работать без уведомлений.

Новые заявки и напоминания из CRM приходят автоматически без персональных данных, со
ссылкой «Открыть заявку в CRM». В Telegram нет кнопок подтверждения/отказа;
статус заявки меняется в CRM. Ссылка открывает страницу заказа; при необходимости
нужно войти под аккаунтом мастера. Русская/казахская анкета клиента не меняется.
Уведомления проверяются в цикле polling, обычно с задержкой до 25–30 секунд.
При первом включении старые уведомления не рассылаются; после перезапуска
недоставленные новые уведомления из CRM догоняются. SQLite хранит очередь и
ID обработанных уведомлений. Не удаляйте BOT_STATE_PATH.
В редком сбое после фактической отправки Telegram может повторить сообщение;
повторного заказа это не создаёт. Блокировка бота мастером или неверный Chat ID
фиксируются в консоли и не мешают клиентам; после исправления проверьте новой заявкой.
Один запущенный бот с этими настройками — один мастер и его Chat ID.

## Работа по всему Алматы

В CRM у мастера укажите город `Алматы`, список районов оставьте пустым — весь город.
В актуальной CRM это также можно сделать командой `configure_almaty --phone НОМЕР`.
API возвращает `service_districts` со всеми 8 районами; бот предлагает их на русском
и казахском, сохраняя единое русское название района в заказе. Явно заданные районы
в профиле остаются ограничением; для работы по всему городу очистите их.
Обновите CRM до актуальной версии, чтобы получить полный каталог.

# Установка атомарного API в Flowza CRM

Модуль рассчитан на `KuatBakyt/flowza-crm` с Django 5.2 и текущими приложениями `accounts` и `crm`. Он поставляется отдельно, без автоматического изменения этого репозитория.

## Установка на Windows

Если репозитории находятся рядом:

```powershell
# В папке testbot_client_flowza
Copy-Item -Recurse -Force .\integrations\flowza_bot_api ..\flowza-crm\
```

В `flowza-crm/config/settings.py` после определения `INSTALLED_APPS` добавьте:

```python
INSTALLED_APPS += ['flowza_bot_api']
```

В `flowza-crm/config/urls.py` добавьте маршрут **перед** общим `/api/v1/`:

```python
path('api/v1/bot/', include('flowza_bot_api.urls')),
```

`path` и `include` уже импортированы в текущем проекте Flowza. Не заменяйте существующие маршруты.

Пересоберите API и примените миграции. В папке CRM:

```powershell
docker compose build
docker compose run --rm api python manage.py migrate
docker compose up -d
```

Если сервис Django в вашем compose имеет другое имя, замените `api` его именем (`docker compose config --services`). При запуске без Docker: `python manage.py migrate`, затем перезапустите Django.

Проверьте Swagger `http://localhost:8000/api/docs/`: появится раздел **Bot**, `POST /api/v1/bot/orders/`. Авторизуйтесь JWT мастера. Проверка ботом `--check` использует `OPTIONS` и не создаёт заказа.

## Контракт

```json
{
  "request_id": "9c70decc-b889-4e85-a20d-e21d4b2b2bd2",
  "client": {
    "name": "Әлия",
    "phone": "+77012345678",
    "external_id": "telegram:123456:987654"
  },
  "order": {
    "specialization": "UUID_ИЗ_CRM",
    "title": "Сантехника",
    "description": "Кран ағып тұр",
    "address": "Алматы, Абая 10",
    "district": "Бостандыкский",
    "start_at": "2026-10-05T05:00:00Z",
    "end_at": "2026-10-05T06:00:00Z"
  }
}
```

Пример даты подходит только до её наступления; при ручном тесте используйте будущее время. API не принимает master, status, source, final_price и другие посторонние поля. MASTER назначается из JWT, `BOT` и `NEW` задаются сервером.

Ответ при первом создании — HTTP 201:

```json
{"id":"UUID_ЗАКАЗА","client_id":"UUID_КЛИЕНТА","status":"NEW","replayed":false}
```

Повтор с тем же ключом и точными данными — HTTP 200 с теми же идентификаторами и `replayed=true`. Изменение данных под старым ключом — HTTP 409 `idempotency_conflict`. Ключ ограничен аккаунтом мастера. Результат квитанции остаётся доступен этому аккаунту после изменения статуса или передачи заказа; чужие детали заказа не возвращаются.

Создание клиента, заказа, истории, квитанции и уведомления выполняется в одной транзакции. PostgreSQL блокирует стабильную строку пользователя для сериализации одновременных повторов; уникальное ограничение дополнительно защищает ключ. Повторные обращения ищут клиента по `created_by` и `external_id`, затем обновляют имя и телефон.

Проверяются активность мастера, его специализация, будущая дата до 365 дней и занятость подтверждёнными заказами/блоками. NEW не создаёт календарного блока; бронирование выполняется при подтверждении мастером. SQLite подходит для локального последовательного теста; для одновременных запросов используйте штатный PostgreSQL CRM.

Авторизация и формат ошибок наследуются от Flowza CRM. Внешним клиентам Telegram JWT не выдаётся — он хранится только в процессе бота.
